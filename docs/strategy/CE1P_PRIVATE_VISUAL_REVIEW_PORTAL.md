# CE-1P — Protected offline visual review interface

**Checkpoint date:** 2026-11-09. **Status:** private engineering implementation, pending exact-head CI and merged-baseline checks. No real outside reviewer, production host, customer release, or broker action.

## Deliverable and dependency-aware flow

CE-1K verifies signed-staged original issuer PDFs and source-to-claim citations. CE-1M renders all PDF pages to deterministic PNG files. CE-1N seals the **actual rendered image bytes**, full attributed dossier, all supporting and contrary sources, source-page citations and hash-linked worklist into a separate read-only private workroom, with disposable real Linux UID access tests. CE-1O builds a **blank** page-by-page and claim-by-claim observation worklist and validates a current-root-governed, short-lived signed reviewer receipt; metadata-only compliance remains HOLD.

**CE-1P implements a usable offline visual interface, not a fake completed review.** The new `src/company_os/competitive_review_portal.py` reads the current sealed room and the unanswered CE-1O worklist, independently re-hashes **every page PNG**, and creates one **self-contained, private, read-only HTML file**. Each original page image is embedded inline using its exact verified bytes—no localhost web server, no remote URLs, no external dependencies, no browser telemetry, and no external image/CDN asset dependency.

The page displays the source image at readable scale, identifies its document/page and SHA-256 digest, and contains a mandatory *manually selected* visual finding plus substantial page-specific notes. Every **dossier claim** is displayed, including classification, full claim text, the exact source excerpt and publisher/original source URL **as text only**, all supporting IDs, every counterevidence ID, and local links to any captured original-issuer excerpt page. Sources not contained as originals are visibly labeled **“Original not in sealed issuer-PDF packet.”**

Reviewer controls are intentionally blank. There are exactly three page findings—`legible_reported`, `defect_reported`, `unassessable`—and three claim dispositions—`unverified`, `contradiction_reported`, `packet_excerpt_located`. The last option is unavailable when a claim has no original issuer PDF citation in this packet. Original excerpt located **does not** imply source truth or third-party issuer authentication.

Reviewers can **save an unsigned private draft**, reopen it only when it matches the precise sealed room digest and every original page/claim identity, and continue their actual examination. They can export a complete **unsigned** observation JSON only after providing 36–1200 characters of notes for every source page, 48–1500 characters of reasoning for every claim, choosing every disposition manually, and supplying 60–2000 characters of overall limitations and findings. Export includes the exact room, dossier, issuer inventory and handoff hashes, relevant citations, times, and **explicit `publication_authorized=false`, `independent_critic_approved=false`** flags. Separate protected reviewer identity verification, policy/revocation, authorized signing, rigorous independent CE-1O / CE-3A validation, and any release decision must happen *outside* this interface.

## Privacy and execution model

- No HTTP listener, network requests, hosted services, public links or third-party assets are added. The HTML has a restrictive **Content Security Policy**: default/connection/object/frame/form resources blocked; images may only be embedded PNG data URIs; inline script and CSS require exact SHA-256 hashes. External source URLs appear as **nonclickable literal text**, not links.
- Untrusted dossier/source/claim strings are HTML-escaped before insertion. Dynamic JSON escapes `<`, `>` and `&` so malicious source text cannot terminate the inert JSON script block or run injected browser code. The JavaScript does not submit data to a server, use storage/network APIs, sign or approve.
- The portal file is staged as an **exclusive**, read-only `0400` HTML file in a private `0500` directory alongside the original sealed room. A separately audited OS provisioner must grant group read-only access to the approved reviewer while the creator/capture UID cannot read that private reviewer copy. The existing cross-UID GitHub exercise now includes the self-contained page itself and denies unauthorized reads and reviewer writes. The portal output is a **confidential work product and must never be committed to a public repository, added to a GitHub artifact, or hosted publicly.**
- Opening local HTML with `file://` may behave differently across browser security configurations. The inline page images and review form require modern browser support for data URLs, same-page JavaScript, Blob download and File APIs. A production-approved reviewer browser should be visually tested in that exact environment before anyone relies on it.
- Browser-generated draft and unsigned review downloads can contain private notes. The application cannot enforce the user's browser downloads directory, clipboard or device backup; use a protected workstation/download location and retention policy. Browser filesystem may not itself guarantee host-level separation.
- The packed HTML is bounded to 98 MiB: **all pages must fit, or creation refuses to complete**; it must never truncate pages or sources. Large evidence sets may need a subsequent approved, chunked private-viewer protocol. The original sealed-room bound remains 120 pages / 64 MiB.
- Static pages and browser interaction do not establish a real independent qualified critic, that images were actually viewed, or that findings are correct. JS-only input checks are convenience; **CE-1O's independent server-side signed receipt checks remain mandatory**. A signed document is still not factual source authentication or production approval.
